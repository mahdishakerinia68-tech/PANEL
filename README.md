# STRIX VIP PANEL V1.1.1

## رفع ایراد نسبت به نسخه قبل
- **باگ اصلی:** چون `JWT_SECRET` تنظیم نشده بود، هر بار که سرور Restart می‌شد (کرش، دیپلوی مجدد، ری‌استارت سرویس) یک Secret تصادفی جدید ساخته می‌شد و همه Sessionها (ادمین + همه کاربران پنل/فروشنده‌ها) بی‌صدا Logout می‌شدند. الان Secret در فایل `backend/.jwt-secret` ذخیره می‌شود و بین Restartها ثابت می‌ماند. برای Production بازهم توصیه می‌شود خودتان `JWT_SECRET` را در `.env` ست کنید.
- Rate limit ساده روی `/api/auth/login` و `/api/setup/create-admin` اضافه شد تا حدس رمز (Brute force) روی پنلی که حساب‌های پولی می‌فروشد سخت‌تر شود.
- پیام خطاهای فارسی برای مواردی مثل رمز/آیدی اشتباه، نشست منقضی و... کامل شد (قبلاً بعضی کدهای خطای انگلیسی خام نمایش داده می‌شد).
- چند هدر امنیتی ساده (X-Content-Type-Options، X-Frame-Options) اضافه شد.


پنل مدیریتی مشکی/طلایی با ساختار نزدیک به پنل Marzban، احراز هویت واقعی Backend و دیتابیس SQLite.

## اجرا
```bash
cd backend
npm install
cp .env.example .env
# JWT_SECRET را در .env با یک مقدار تصادفی قوی تنظیم کنید.
npm start
```

سپس فایل‌های ریشه را با یک Static Server سرو کنید و API را روی همان Origin یا با Proxy به Backend متصل کنید.


### نکته مهم درباره ساختار «پنل مادر»
این پروژه یک لایه مدیریتی (Auth + دیتابیس کاربران/سرویس/پلن/سرور) است؛ بخش «کاربران پنل» همان مکانیزم ریسلر/زیرمجموعه شماست: هر Panel User فقط رکوردهای خودش (customer_id) را می‌بیند و مدیریت می‌کند، و شما به‌عنوان ادمین همه را می‌بینید — این معماری برای «پنل مادر + زیرپنل فروشنده» درست است.
اما این نسخه به هیچ هسته واقعی VPN (مثل Marzban، 3x-ui یا Hiddify) وصل نیست؛ جدول «سرورها» و «سرویس‌ها» فقط اطلاعات را ذخیره می‌کند و خودش کاربر VPN واقعی نمی‌سازد. اگر می‌خواهید با کلیک «ساخت کاربر» یک اکانت واقعی روی سرور بسازد، باید API همان پنل (Marzban/3x-ui/...) را در `backend/server.js` صدا بزنید — بگویید از کدام پنل استفاده می‌کنید تا آن اتصال را هم برایتان اضافه کنم.

### چک‌لیست قبل از رفتن به Production
- `JWT_SECRET` را در `.env` با یک مقدار تصادفی طولانی (مثلاً خروجی `openssl rand -hex 48`) ست کنید.
- پنل را پشت Nginx با HTTPS (Let's Encrypt) بیاورید؛ هیچ‌وقت پنل فروش را روی HTTP خام در دسترس عموم نگذارید.
- فایل `strix.db` و `.jwt-secret` را Backup منظم بگیرید و در Git کامیت نکنید (در `.gitignore` هست).
- برای اجرای دائمی از `pm2 start server.js --name strix` یا یک systemd service استفاده کنید تا با ری‌استارت سرور، پنل هم بالا بیاید.

### مهم برای ورود
برای اجرای کامل پنل، Frontend و Backend را از یک سرور اجرا کنید: داخل `backend/` دستور `npm install` و سپس `npm start` را اجرا کنید و پنل را از `http://SERVER:3000/` باز کنید. باز کردن مستقیم `index.html` با `file://` یا فقط GitHub Pages باعث می‌شود APIهای Login/Setup به Backend وصل نشوند. اگر Frontend روی دامنه جداست، قبل از `app.js` مقدار `window.STRIX_API_BASE` را برابر آدرس Backend قرار دهید.
